# 1.0.3 广告解锁设计

## 目标与边界

为按顺序播放到首个锁定集、且未通过现有充值、金币或会员流程解锁的用户，提供自营广告解锁。广告素材预加载、广告会话、有效观看计时与确认解锁为独立模块；服务端是广告资格、次数、会话有效性和权益授予的唯一权威。

本期不改变现有充值、金币、会员解锁流程，也不为服务端的会员、顺序或次数错误码建立客户端业务分支。跳集永不展示广告解锁。

## 触发与展示流程

1. 当前短剧首次实际开始播放后，异步确保本地有一个待消费广告素材缓存。
2. 用户按顺序进入首个锁定集时，先完整走现有充值/金币/会员解锁弹窗。
3. 用户通过原流程解锁成功时，广告流程终止；用户关闭弹窗且仍未解锁时，查询 `GET /api/ad/unlock/status`，携带 `drama_id` 与 `episode_no`。
4. 仅当服务端广告开关开启、当前集不是跳集/无效集、且对应普通或会员专属短剧仍有次数时，展示广告解锁弹窗。关闭广告解锁弹窗后进入既有解锁提示。
5. 既有按顺序解锁提示在服务端广告开关开启时显示“看视频解锁”。次数耗尽时保留按钮；点击后按短剧类型提示当日上限。跳集提示不显示广告入口。
6. 点击“看视频解锁”后，先在客户端检查当前服务端次数快照；有剩余次数才调用 `POST /api/ad/session`，传 `drama_id`、`episode_no` 和本地预加载素材的 `material_id`。
7. 创建成功后进入全屏自营广告页。创建或确认接口的失败均以服务端返回为准，必要时重新请求广告状态并回退到既有解锁提示。

## 接口契约

### 广告状态

`GET /api/ad/unlock/status`

请求参数：`drama_id`、`episode_no`（均使用 snake_case）。客户端使用 `unlock_enabled`、普通/会员次数字段、`episode_unlock_status` 与 `reset_time` 决定展示状态。每日重置不由客户端计算。

### 素材预加载

`GET /api/ad/material/preload`

本地无缓存时不传参数；有缓存时传 `material_id`。服务端返回 `material_id`、`file_url`、`material_type`（1 图片、2 视频）。同一素材且本地文件完整时不重复下载；新素材以原子写入方式落盘，并保存素材元数据与本地路径。

### 创建会话

`POST /api/ad/session`

```json
{
  "drama_id": 0,
  "episode_no": 0,
  "material_id": 0
}
```

返回 `session_no`、实际分发的素材信息、`h5_url`、`watch_seconds`、`expire_at` 与 `reused`。客户端以返回素材为准；必要时下载并替换缓存。`reused=1` 表示服务端复用未完成会话。

### 确认解锁

`POST /api/ad/session/confirm`

```json
{
  "session_no": "string",
  "watch_seconds": 0
}
```

确认成功才将当前集的会话内权益更新为 `ad` 并恢复播放。网络失败时保留广告页并允许以相同 `session_no` 和累计时长重试；客户端在服务端成功前不得视为已解锁。

## 素材缓存策略

缓存容量固定为一个待消费素材。首次真实播放后开始预加载；缓存数量少于一个时继续补齐。当前素材被广告会话消费后立即异步预加载下一个。下载失败不得影响短剧播放，后续满足缺缓存条件时再试。缓存只保存素材，不创建会话、不消耗次数。

## 有效观看状态机

广告页区分 `loading`、`watching`、`readyToConfirm`、`confirming`、`confirmRetry`、`confirmed` 与 `terminalFailure`。

- 图片在成功展示后计时；视频只在实际播放时计时，且循环播放。
- 普通后台、锁屏和主动退出广告页均暂停有效观看；未达标时不能关闭，系统返回键同样拦截。
- 用户点击素材打开服务端配置的站外 H5 后是唯一例外：继续累计有效观看；返回广告页后恢复素材展示。
- 达到 `watch_seconds` 后停止计时并立即确认。确认中及确认失败的重试态均不允许关闭。
- 确认失败显示“重试解锁”；会话过期或素材加载失败时不解锁、不计成功次数，并回退至既有解锁提示后由用户重新发起。

## 架构与职责

新增 `features/ad_unlock/`：

- `domain`：状态、素材、会话和值班计时模型；
- `data`：四个接口 DTO、Repository 与本地单素材缓存；
- `application`：预加载器、会话控制器、有效观看控制器；
- `presentation`：广告解锁弹窗与全屏自营广告页。

播放器侧只负责：首次真实播放通知预加载器；原解锁弹窗关闭且未解锁后调用广告协调器；确认成功后更新当前集权益、在当前锁定点续播。现有本地倒计时完成后直接标记 `ad` 解锁的临时逻辑必须移除。

## 埋点

沿用现有 `ad_unlock_entry_exposure`、`ad_view_start` 和 `ad_view_end`。广告结束结果至少区分：确认成功、确认待重试、提前退出、素材失败、会话失效；携带 `session_no`、`material_id`、短剧/剧集标识和累计有效观看时长。

## 验收与测试

覆盖普通及会员专属短剧、跳集、原解锁成功/关闭、次数耗尽、缓存复用和失败、图片/视频/H5 计时、后台/锁屏暂停、会话复用、确认失败重试、会话过期、返回键拦截和确认成功后的原位续播。所有 API、状态机和播放器集成均需有单元或组件测试。
